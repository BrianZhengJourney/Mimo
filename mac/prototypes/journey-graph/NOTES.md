# Journey graph redesign prototype

**Question:** 今日手记的 journey graph 应该往哪个设计方向走,才能更美、更有设计感、更 human?

三个结构不同的变体(`index.html`,浏览器直接打开,`?variant=` 或底部浮条/方向键切换):

- **甲 · 手卷** — 一天是一条手绘墨线,从晨到暮横向展开。折叠空闲时间,大停留是墨点,回访主题 hover 时以细线串起。时间叙事优先。
- **乙 · 庭园** — 主题是庭园里的石头(有机墨染形状),面积 = 时长,按初访时间流式排布,虚线足迹按时间顺序穿行其间。主题优先。
- **丙 · 册页** — 完全不用图:一天排成一页手记,章节 + 碎片时刻 + 休息分隔,类别色手绘下划线。检验"也许根本不需要 diagram"。

共同约束:>30 分钟空闲折叠;连续同源片段合并;印章红(朱砂)是唯一新增色,只用于"往日也来过"的印。双数据集(密集 39 段 / 稀疏 5 段)可切换。

**Answer:** Brian 选了**乙 · 庭园**,方向是"越 interactive 越 intuitive"。已在原型里加深交互:

- 点石头 → 下方明细条展开该主题的每次回访(时间 · 时长链)
- 拖一块石头到另一块上 → 合并主题(带撤销 toast)
- 双击石头 → 就地改名(Enter 确认 / Esc 取消,带撤销)

合并/改名在内存里模拟的正是 `journey_graph.swift` 里 `JourneyGraphCorrections`(labels/merges)的语义,回迁 reflection.html 时可以直接接上。甲的"墨线+折叠空闲"思路可作为时间布局的改造参考;丙的叙事文案风格可喂给右侧回看面板。

**已落地(2026-08-07):** 乙·庭园 → reflection.html 主题布局;甲·手卷 → reflection.html 时间布局。拖动合并被砍(Brian: doesn't feel meaningful),合并/改名走已有的"整理这个主题"弹窗(明细条入口,Swift `editTopic` bridge)。下方 30 分钟格子改为点击过滤时间线、再点退出。本目录保留作设计参考,确认稳定后可删。
