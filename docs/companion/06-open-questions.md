- **Q10(原)自动重掷的花费上限** —— 已澄清,处置如下:

  **问题**:一致性闸门自动重掷不合格的格子,每次都是付费调用。
  用户在领养页看到的是"+1 次调用",但若这只伴灵恰好是模型画不稳的类型,
  闸门可能连续重试多次,**实际花费数倍于用户预期,且全程静默**。

  **决定**:
  - 单张 actionSheet **最多自动重掷 3 次**(整表或单格合计)
  - 到达上限后**停止自动重试**,把**分数最好的一次**结果连同一致性
    评分展示给用户,由用户决定接受 / 手动再花钱重来
  - UI 上**显示已重试次数与累计花费**,不静默
  - 硬编码兜底上限独立于配置,防止配置错误导致失控
  - 所有重掷仍走 `generation_ledger` 的预留守卫

  **原则:宁可让用户看到一只稍不完美的伴灵,也不要静默烧钱。**

  > 🔬 **开发期要求:保留全部 1–3 次尝试,不要只留最好的那次。**
  > `generation_draft.swift` 在 debug / 内测构建下应把**每一次尝试的原始
  > PNG 与其一致性评分**都留档(release 构建仍只留最好的一次,避免
  > 磁盘膨胀 —— 每份草稿 5–15MB)。
  >
  > 理由:我们需要看清**同一个 prompt 的第 1/2/3 次到底差在哪** ——
  > 是整体风格漂移、还是只有某几格坏、是随机的还是系统性偏向某个方向。
  > 这直接决定三件事:`T_pass`/`T_fail` 阈值怎么定、
  > 单格重掷 vs 整表重掷的分界线画在哪、以及重试上限 3 是否合理
  > (如果第 3 次几乎从不比第 2 次好,那上限应该降到 2)。
  > **这是 §4.10 阈值标定的主要数据来源。**
